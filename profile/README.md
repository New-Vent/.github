#### 1. 벤치마크 결과를 바탕으로 LLM의 HTML 생성·수정 방식을 어떻게 결정하면 좋을까요?

여러 로컬 LLM으로 HTML 생성·수정 파이프라인을 벤치마크했지만, 현재 테스트에서는 뚜렷하게 적합한 모델을 찾지 못했습니다. 외부 모델 API 사용도 가능한 상황이며, 최종 모델과 생성·수정 방식은 아직 정하지 않았습니다.

이 결과를 바탕으로 모델 변경, 프롬프트·파이프라인 개선, 생성·수정 범위 조정 중 무엇을 우선 검토하면 좋을까요? 추가 실험의 방향을 정하는 기준이 궁금합니다.

현재 생성 방식 중에 JSON/HTML 방식에서 고민중이고, 기존 JSON 방식에서 ~~페이지를 제작해줘라고 할 경우
- 텍스트 필드에 <strong>1단계:</strong> 과 같은 HTML 태그가 들어가는 이슈와 같은 콘텐츠 생성 자체를 LLM이 힘들어합니다
- 그래서 현재 테스트 방법 중 J-STRUCT:{"type":"benefits","itemCount":3} 방식으로 구조만 LLM이 생성 후 서버에서 해당 구조대로 HTML을 생성 후 내부 콘텐츠를 사용자에게 입력 받는 방식을 테스트하였습니다.

#### 4. LLM이 요청하지 않은 혜택·날짜·참여 조건을 생성하거나 변경하는 문제는 어떻게 검증하나요?
